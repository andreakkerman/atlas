# Audit evidence — 28 September 2026

These are retained measurements, not production instrumentation or a permanent test suite. See [the report](D:/DevProjects/SvenAdventure/Docs/AUDIT_FOLLOWUP_2026-09-28.md) for interpretation and limitations. The disposable scripts and test copy were removed as requested.

- `graphics-chromium-{1,2}.json`: authored LVL-0004 baseline, isolated features, combinations, OFF states, repeated cycles, paused-producer diagnostic, native texture/buffer lifetime and pass recipes. About 900 ms settling and 2.5-second main samples; 1180×734 CSS, real WebGPU API. Chromium launched with `channel: chromium` and `--enable-unsafe-webgpu`. `counts` is cumulative within each sample; divide by `counts.frames` for per-frame values. Resource flags in pass recipes can show later destruction within that sample's object snapshot; `live` is the end-of-sample inventory.
- `graphics-webkit-2.json`, `firefox-capability.json`: fallback/availability evidence. Firefox's initial measurement timeout in the graphics log is explained by its separately verified `adapter-unavailable` status.
- `off-state.json`: normal-animation ownership/opacity/blank-Canvas checks after OFF transitions. `fixed-appearance.json` records identical Canvas pixel hashes with time frozen. `fixed-off.png` and `fixed-depth.png` show the isolated visual discontinuity. `pixel-comparison.json` reports the OFF return's exact pixel match.
- `neutral-*.png`, `neutral-pixel-comparison.json`: separate DPR-1 frozen diagnostic. Only the GPU uniform for depth perspective (Float32 index 74) was zeroed in the labeled variant; full-scene architecture remained selected. Restoring that uniform isolates the intended tint from the path change. This intervention was never used for performance measurements.
- `audio-{chromium,webkit}-healthy.json`: native `play()` delegation, events, current time, peak volume, production runtime ownership/readiness and group starts. First two Swift groups kept authored timing; later idle gaps were compressed to 300 ms. Four Swift members share one During call. Level transition used LVL-0032 Wasp.
- `audio-*-failed.json`: first preload HTTP failure, restored network, subsequent groups and re-entry. Chromium used Playwright request routing. WebKit used a temporary loopback HTTP proxy to the existing asset server because native media bypassed Playwright routing. The initial WebKit fault section in `audit-followup-audio.log` had zero intercepted requests and is **not valid fault evidence**; `audit-webkit-faults.log` and the final WebKit JSON replace it.
- `audio-*-delayed.json`: readiness timing with compressed idle gaps; first flight silent, subsequent flight recovered. `audio-natural-*.json` and screenshots separately verify a failed first flight at unchanged authored scheduling, and cancellation of a pending native play before releasing the network. Re-entry idle gaps in those probes were compressed and labeled.
- `audit-native-tests.log`: 16 assertions from a disposable bootstrap-repaired copy of `tests/flyby-audio.spec.js`; 11 passed, 5 failed. Command: `npx.cmd playwright test tests/audit-flyby-native.spec.js --project=desktop-chromium --project=ipad-landscape --workers=1 --grep-invert Apply`. Apply was excluded to avoid authored writes. Existing assertions were retained.
- `audit-native-taps.log`: diagnostic rerun of four native tap tests with additional hit logging, unchanged assertions: 2 passed, 2 failed. Both remaining failures had null hits at the test's chosen Swift centre. The report preserves the other test limitations.
- `audit-followup-baseline.json`, `cleanup-hashes.json`, `cleanup-git.txt`: before/after source fingerprints and final non-destructive checks. `screenshot-hashes.json` includes all generated screenshots before pruning redundant files; identical return-OFF images were pruned after recording their hashes and zero pixel difference.

Service workers were blocked in disposable browser contexts. Production reporting was enabled in the primary diagnostics using `atlasSessionTest=1`; the existing native test copy retains its original narrower reporting/preview assumptions. No physical iPad or audible speaker test was performed. No dependency or GPU preset changes were made.
