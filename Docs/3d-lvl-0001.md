# LVL-0001 first-person 3D

Graphics → 3D loads a spatial Blender-authored forest and temple through Three.js 0.180.0 and WebGPU. Atlas owns progression, questions, NPC state, route position and the Graphics preference. The route follows the authored LVL-0001 journey with a 1.58 m eye height. W/S walks the constrained route; dragging looks around; A/D turns; E uses the facing landmark.

## Input and preparation

Selecting 3D closes Graphics and returns keyboard focus to the prepared canvas. Clicking the world also dismisses a reopened Graphics panel. Keyboard and pointer input share the same readiness/dialog guard; held inputs reset on blur, visibility changes, pointer cancellation and challenges. Arrow keys are alternatives to W/S/A/D. Double-click optionally locks the mouse; Escape releases it. The contextual action can also be clicked.

The reported desktop failure was reproduced with real browser input: Graphics remained open, W left the player at x=175, but dragging changed yaw from -0.08 to -0.52. Closing Graphics restored walking. The old integration test hid this problem by explicitly closing Graphics and focusing the canvas. The revised test uses the ordinary selection flow and starts walking immediately.

The opaque preparation screen covers the world until decoded GLB/HDR resources, the NPC frame, the HDR world-pass material pipelines, and the complete AO/volume/bloom/shadow render chain are prepared. Compilation includes geometry behind the initial camera. Hidden renders cover six directions at three route positions, followed by the actual player view at the current viewport size. Every render awaits Three.js `waitForGPU()`. The final view is restored and submitted before readiness. Stage descriptions replace fake percentages; no timer determines readiness. Switching modes invalidates pending preparation through the existing generation token.

The loading indicator has five discrete segments: engine initialization, world/model data, material preparation, WebGPU/lighting/shadow warm-up, and the final playable frame. Completed segments advance only at existing successful completion boundaries. During GPU warm-up, the existing GPU-completed view counter supplies a real `n of 18` detail; the final player view remains a separate last stage. There is no estimated remaining time, percentage interpolation, or added delay. The accessible progress bar reports completed stages rather than elapsed time.

Touch devices use a left analog pad for route movement and turning, a separate drag anywhere on the world for looking, and a contextual action button on the right. Pointer IDs keep simultaneous movement and looking independent. Touch cancellation releases movement. The controls sit above the guide strip, respect safe areas, and coexist with mouse and keyboard. Physical iPad performance still requires device testing; Chromium touch emulation exercises the browser pointer-event path.

The small gameplay performance HUD is independent of the Graphics panel and has no pointer or keyboard focus target. FPS and CPU render-frame time refresh about four times per second. Preparation is the measured elapsed time from 3D initialization through the completed GPU warm-up and final frame; the last successful duration remains stable across HUD/dialog redraws and cancelled preparation. It is unavailable until a preparation has completed. The HUD is only mounted for the supported active 3D view; the existing Graphics status readout remains available.

Control hints default to the device's pointer capability, then follow deliberate gameplay mouse/keyboard or touch/pen input. The selected input type survives Atlas UI redraws, including Graphics and challenge panels. Touch hints include movement, looking and tapping the contextual action. `touch-action: none`, selection/callout suppression and overscroll containment apply to the canvas and movement pad. Non-passive touch-move and Safari gesture guards are scoped to those gameplay targets while play is enabled; menu controls and challenge forms are not globally blocked.

## Authoring and runtime assets

The editable source is `Levels/LVL-0001/3d/lvl0001.blend`, scene **Atlas LVL-0001 First Person**. Its GLB contains terrain, volumetric trunks and branches, folded foliage, scanned rock meshes, varied ground plants, solid runestones, temple masonry, guardians, doors and stair courses. Freya currently uses the existing animated Atlas sprite on a spatial billboard.

The runtime loads `lvl0001.glb`, `route.json` and the local sunset HDR. It uses shared GPU instances, spatial batches, PBR albedo/normal/roughness maps, directional shadows, local rune/fire lights, depth-limited volume scattering and bloom. The moss shader blends the authored surface material using world-space noise and slope. Foliage alpha maps are cutouts. The atmosphere pass has a separate camera layer, while the world shadow camera retains its own layer mask.

The Blender source is the authoritative editable checkpoint. The scripts in `scripts/*lvl0001-blender.py` record successive authoring passes; they are **not yet a single clean-room rebuild command**. In particular, source-model imports, carved texture assignments and some early canopy/guardian refinements are already stored in the blend. Continue from the blend rather than rerunning the base scene constructor.

- `build-lvl0001-blender.py`: base terrain, route, landmarks, temple and export.
- `refine-lvl0001-blender.py`: scanned source assets and their authored placements.
- `canopy-lvl0001-blender.py`: solid trunks/branches and folded twig clusters.
- `groundcover-lvl0001-blender.py`: broad paving and detailed plants.
- `finish-lvl0001-blender.py`: connected stair courses, understory, mesh-based grounding.
- `surfaces-lvl0001-blender.py`: cylindrical bark grain and moss authoring surfaces.
- `weather-lvl0001-blender.py`: lichen stone and weathered stair lips.
- `banks-lvl0001-blender.py`: dense route-bank plant communities.
- `broadleaf-lvl0001-blender.py`: periwinkle communities and trailing temple growth.
- `surroundings-lvl0001-blender.py`: surrounding terrain and closed outcrop volumes.
- `enclosure-lvl0001-blender.py`: terrain shoulders, embedded outcrops and varied shrubs.
- `young-trees-lvl0001-blender.py`: distinct juvenile fir geometry, replacing miniature mature trees.
- `bake-carvings-lvl0001-blender.py`: Cycles-baked tangent-space carving relief.
- `spruce-spray-lvl0001-blender.py`: Blender-rendered dense needle spray texture.
- `shape-sprays-lvl0001-blender.py`: drooping mature sprays and fuller juvenile branch coverage.
- `ground-rocks-lvl0001-blender.py`: footprint-based rock contact and ledge shrub grounding.
- `landform-contact-lvl0001-blender.py`: soil shoulders joining outcrop groups to terrain.
- `hazel-lvl0001-blender.py`: three forked broad-leaf sapling structures.
- `temple-creepers-lvl0001-blender.py`: wall growth positioned against masonry geometry.
- `stratified-cliffs-lvl0001-blender.py`: closed stepped rock masses for the rear enclosure.
- `roots-lvl0001-blender.py`: root flares conforming to hillside height.
- `root-collars-lvl0001-blender.py`: soil plates joining mature roots to slopes.
- `place-scanned-firs-lvl0001-blender.py`: selected scanned mature-tree placements. The saved scene subsequently uses a separate foliage derivative over solid trunk cores; the original scanned master remains in the source library for reversal.
- `export-lvl0001-blender.py`: export-only operation on the current scene, packing its textures.
- `scanned-banks-lvl0001-blender.py`: reduced Poly Haven rock-ground patches conformed to the enclosure banks.
- `scanned-cliffs-lvl0001-blender.py`: scanned rock shelves replacing stretched cliff proxies, plus broad underside contact corrections. Original proxies remain in the source library.
- `irregular-stairs-lvl0001-blender.py`: varied stone widths and staggered joints at the existing route elevations.
- `library-understory-lvl0001-blender.py` and `place-library-understory-lvl0001-blender.py`: independent library LODs and selected sapling/small-tree replacements, retaining the prior objects in the source library.

Use Blender MCP to execute authoring passes. Preserve unrelated Blender scenes. Export only the active Atlas scene with Y-up, applied modifiers, GPU instances and embedded WebP textures. Lights/cameras remain in the editable source; runtime lighting is configured in `src/three-renderer.js`.

Geometry delivery uses Draco compression with a local Three.js r180 decoder (two workers). The first compression comparison reduced the same scene from 185,137,532 to 55,226,600 bytes; 423 primitives used `KHR_draco_mesh_compression`. All ten WebGPU capture positions loaded without runtime errors. Later library landforms add some geometry and textures, so the current file is larger than that comparison checkpoint. The full three-test integration suite passed after the loader change on 2026-09-06 (2.7 minutes).
